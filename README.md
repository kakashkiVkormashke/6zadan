# Арканоид — Android / Kotlin

Игра по методичке «Создание игры “Арканоид” шаг за шагом», включая все шесть домашних заданий.

## Возможности

- Белые мяч и ракетка, отскоки от стен и кирпичей, ускорение с ограничением скорости.
- Восемь столбцов кирпичей; уровни с 3, 5 и 7 рядами. После третьего — победа.
- Каждый пятый уничтоженный кирпич вызывает выпадение бонуса из позиции случайного кирпича среди пяти только что уничтоженных. Типы чередуются: синий дополнительный мяч, зелёная широкая ракетка, красная бомба.
- Синий «+» добавляет мяч; проигрыш наступает, только когда потеряны все мячи.
- Зелёный «↔» увеличивает ракетку в 1,5 раза на 10 игровых секунд. Повторный бонус обновляет таймер.
- Красный «!» уничтожает кирпичи в радиусе 100 логических пикселей от исходной позиции бонуса. За каждый кирпич начисляется очко, взрыв показан красным кругом.
- Рекорд сохраняется в SharedPreferences, кнопки «Пауза» и «Новая игра».
- При уходе приложения в фон игровое время останавливается.

Управление: ведите пальцем по игровому полю. Ракетка следует за пальцем по горизонтали.

## Запуск

1. Откройте корень репозитория в Android Studio, дождитесь Gradle Sync.
2. Установите Android SDK Platform 35 и Build Tools 35.0.0 через SDK Manager.
3. Выберите устройство или эмулятор Android 7.0 (API 24) и новее, нажмите Run.

Для сборки из терминала нужны JDK 17 или 21, Android SDK и `ANDROID_HOME` либо `sdk.dir` в локальном `local.properties`:

```sh
./gradlew testDebugUnitTest lintDebug assembleDebug
```

Windows: `gradlew.bat testDebugUnitTest lintDebug assembleDebug`.
APK: `app/build/outputs/apk/debug/app-debug.apk`. GitHub Actions также собирает APK и сохраняет его как артефакт `arkanoid-debug`.

## Устройство проекта

- `MainActivity.kt` — кнопки и жизненный цикл.
- `GameView.kt` — Canvas, касания и анимация в UI-потоке.
- `GameEngine.kt` — игровая логика без зависимости от Android.
- `Brick.kt` — геометрия кирпича.
- `GameEngineTest.kt` — тесты столкновений, уровней, бонусов и завершения игры.

Поле масштабируется из логических 1080 × 1600 с сохранением пропорций. В отличие от исходного примера, отдельный поток SurfaceView не нужен: ввод, сброс и отрисовка работают последовательно, без гонок. Используются стандартные Android View и Activity, внешняя UI-библиотека не требуется.
